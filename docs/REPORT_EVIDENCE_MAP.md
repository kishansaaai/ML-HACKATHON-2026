## Submission-wide requirements from Deliverables.pdf

- Repository must contain source for data processing, feature engineering, every model tried, evaluation, Bayesian search, decoder, API, UI, deployment and visualisations; it must be public and contain no secrets.
- README must give installation, execution and deployment instructions. Saved model weights, configs, experiment logs and result summaries must be included.
- Submit exactly one consolidated PDF, with sections 2.2, 3.1, 3.2, 3.3, 4, 5, 6 and 7. Every number and chart must be reproducible from repository outputs.
- Section 2.2 must describe preprocessing, observed patterns and feature rationale, missing-value analysis, GPS/road-network plots, a Folium map and each partition used.
- Section 3.1 must compare at least five trained models in the prescribed columns. Section 3.2 must answer all required questions for every trained model. Section 3.3 needs CV Macro F1, student-test Top-1 and Macro F1, and applicable Log Loss plots for every learned model. Training curves are only allowed when the model actually records epoch-wise histories.
- Section 4 must state the Bayesian search space, ranges, objective, trial count and best parameters, then compare tuned and untuned models on the same partitions using CV Macro F1, student-test Top-1, Macro F1, Log Loss and inference time.
- Section 5 must explain the actual HMM implementation and compare classifier-only against decoded predictions, including cases where decoding did not help.
- Section 6 must include an actual Folium map with GPS, road geometry, reference route when available, predicted route, distinct layers/legend and suitable extent/controls. Commit HTML or reproducible map code and include a static export in the PDF.
- Section 7 must contain screenshots of the working UI and successful API responses on the receiving laptop. Screenshots must be captured from the real implementation demonstrated in evaluation.

## Evidence interpretation rules

- Official route continuity is `pathsnap.decoder.metrics.route_continuity`, over all adjacent predicted pairs. Do not substitute the stricter `*_distinct*` columns.
- `student_test` is development evaluation data. The evaluator partition is reserved for the final run.
- Distinguish the nearest-arc and nearest-arc-plus-heading baselines from trained models; use N/A where a baseline has no CV or probability metric.
- The frozen HMM check is recorded in `results/hmm_tuning/final_student_test_check.json`; it reports 0.9021 classifier Top-1 and 0.9071 HMM Top-1 on 19,143 labeled observations, but that is a development check, not final evaluator performance.
- AI assistance may be disclosed, but must not replace the team's independent analysis or be used to fabricate results. Team members must be able to explain the report and implementation.
